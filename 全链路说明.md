## 6. 词法扫描链路

词法分析器接口是 `D:\IT_study\source\temp\compiler-front-theory\src\main\java\org\harvey\vie\theory\lexical\analysis\LexicalAnalyzer.java`。

默认实现是 `D:\IT_study\source\temp\compiler-front-theory\src\main\java\org\harvey\vie\theory\lexical\analysis\DefaultLexicalAnalyzer.java`。

`DefaultLexicalAnalyzer.iterator(...)` 返回：

- `new StatusTableTokenIterator(errorContext, resource.toReader(errorContext), saca, table)`

核心扫描器是 `D:\IT_study\source\temp\compiler-front-theory\src\main\java\org\harvey\vie\theory\lexical\analysis\token\StatusTableTokenIterator.java`。

字段：

- `ErrorContext errorContext`
- `SourceReader reader`
- `SourceAlphabetCharacterAdaptor saca`
- `RegexDfaStatusTable table`
- `ArrayBuilder<byte[]> lexeme`
- `int status`
- `int offset`
- `SourceToken current`

`hasNext()`：

1. `reader.peek()`
2. EOF 时根据 `current` 与 `lexeme` 判断
3. 读字符异常时返回 `true`

`current()`：

- `current == null` 时调用 `next0()`

`next()`：

- `current != null` 时直接消费缓存
- 否则调用 `next0()`

`next0()` 主循环：

1. `read()`
2. EOF 时 `trySplitToken()`
3. `saca.adapt(read)`
4. `UNSUPPORTED` 时 `unsupportedCharacter()`
5. `table.move(status, ac)`
6. `UNKNOWN_CHAR_STATUS` 时 `unsupportedCharacter()`
7. `UNKNOWN_MOVE_STATUS` 时：
   - 先 `trySplitToken()`
   - 再把当前字符附加到新的 `lexeme`
   - 再从起始状态重新移动
8. 正常转移时：
   - `lexeme.append(read.toCharacter())`
   - `status = next`

`trySplitToken()`：

1. `table.accept(status)`
2. `accept == null` 时：
   - `errorContext.addError(new LexicalErrorMessage(offset, "Unfinished tokens"))`
   - 抛出 `CompileException`
3. 否则：
   - `SourceTokenImpl.create(accept, lexeme.toArray(...), offset)`
4. finally 中：
   - `status = table.getStart()`
   - `lexeme.reset()`

## 34. `break / continue` 链路

当前 `break/continue` 不由上下文单独维护池，而是作为未决跳转附着在 `CommandNodeRegister` 上随语义规约向上传递。

生成阶段：

1. `BreakTokenTranslator` 在 shift `break` 时创建一个 `UncertainLabelGotoCommand`
2. 返回 `TokenCommandRegister(command, [break], [])`
3. `ContinueTokenTranslator` 在 shift `continue` 时创建一个 `UncertainLabelGotoCommand`
4. 返回 `TokenCommandRegister(command, [], [continue])`

聚合阶段：

1. `NormalCommandNodeRegister(children, production, childrenRegisters)` 会收集所有子节点的未决 `break`
2. 同时收集所有子节点的未决 `continue`
3. 因此一个复合语句节点天然携带其整棵子树里尚未绑定目标的跳转

绑定阶段：

1. `WhileStatementTranslator` 创建 `whileStartLabel` 与 `whileEndLabel`
2. 条件后插入 `ifn_goto whileEndLabel`
3. 语句体后插入 `goto whileStartLabel`
4. 调用 `bindLoopLabels(body, whileStartLabel, whileEndLabel)`
5. 其中未决 `continue` 绑定到循环头，未决 `break` 绑定到循环尾

`do-while` 绑定阶段：

1. `DoWhileStatementTranslator` 创建 `whileStartLabel`
2. 为条件求值前再建立 `beforeTestLabel`
3. 语句体结束后落下 `beforeTestLabel`
4. 条件为真时 `if_goto whileStartLabel`
5. 调用 `bindLoopLabels(body, beforeTestLabel, whileEndLabel)`
6. 因此 `continue` 会跳到条件检查位置，`break` 会跳到循环尾

程序级拒绝阶段：

1. `ProgramCommandTranslator` 检查顶层结果里的未决 `break`
2. 若仍未绑定，写入 `"break is not allowed here."`
3. 再检查未决 `continue`
4. 若仍未绑定，写入 `"continue is not allowed here."`
5. 只要存在未决跳转，就抛出异常终止语义分析

当前设计不是“每次规约传一个类型栈镜像”，而是把类型属性直接绑定到具体语法树节点：

1. `TypeBuildCallback.onReduce(...)` 取当前规约得到的 `HeadNode`
2. 根据 `production.toString().trim()` 进入 `build(...)`
3. 只有语义上确实有值或有声明类型的节点才返回 `TypeRegister`
4. 没有值的产生式直接返回 `null`，表示该节点不绑定类型属性
5. `context.bindType(head, result)` 把类型属性绑定到当前语法树节点

`TypeRegister` 当前承载三项信息：

- `type`：该节点的语义类型
- `instructionType`：该节点参与指令计算时使用的类型
- `anchor`：用于报错定位的 `SourceToken`

`TypeBuildCallback` 当前处理的核心规则包括：

- 字面量：直接由 `TypeResolver` 判定类型
- 基本类型声明：`type->TYPE_*`
- 数组类型声明：`type->type [ CONSTANT_INTEGER ]`
- 标识符引用：从符号表取 `declaredType`
- 数组取元素：要求左侧是数组，索引必须是 `int32`
- 逻辑表达式：操作数必须为 `boolean`
- 算术表达式：操作数必须为数值类型
- 关系与相等表达式：按规则检查后产生 `boolean`
- 赋值语句与控制语句：需要时读取子节点类型，但这些语句节点本身不绑定值类型

子节点读取辅助由 `TypeAttributes` 提供：

- `child(...)`
- `childType(...)`
- `childInstructionType(...)`
- `childAnchor(...)`
- `result(...)`
- `resultAnchor(...)`

定位 token 的策略：

1. `TypeBuildCallback.anchorOf(...)` 与 `TypeAttributes.anchorOf(...)` 都使用广度优先
2. 从当前子树开始寻找最先遇到的 `TokenNode`
3. 返回其 `SourceToken` 作为定位锚点

命令翻译阶段使用这些类型信息做约束和插入转换：

1. `AssignStatementTranslator` 与 `DeclarationWithInitializationTranslator` 先检查 `requireAssignable(...)`
2. 若 `context.requiresImplicitCast(sourceType, targetType)` 为真，则插入 `st_top_cast`

- 设计原则：**对增加开放，对修改关闭**
    - 以后做功能时，优先新增类、新 Demo、新入口、新适配层
    - 通过“新增并替换接线”的方式实现功能
    - 不把“直接改旧代码”当默认策略

- 修改边界：
    - **测试相关代码**可以直接改
    - **我自己新写的代码**可以继续改
    - **底层代码**不能随便直接改
    - 如果代码注释里的 `author` 是 `Harvey Blocks`，默认视为**不能直接修改**

- 对旧代码的处理方式：
    - 不直接动旧底层实现
    - 先做设计，找扩展点、替换点、包装点
    - 用新的类去承接变化，再用新的入口把它接进去

- 复用要求：
    - 新 代码 不是为了复制旧 代码
    - **能复用就复用，而且复用率要高**
    - 如果在专注于实现语义分析, 像词法分析、语法分析这类已有稳定链路，应该优先复用
    - 新代码只实现真正变化的部分，比如新的语义测试、报告、适配层

- 我的执行策略以后应当是：
    - 先识别哪些旧能力可复用
    - 再识别哪些点需要扩展
    - 优先新增而不是改旧
    - 只在你明确允许时，才直接修改 `Harvey Blocks` 的旧底层代码
